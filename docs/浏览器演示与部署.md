# 浏览器演示与部署

大屏前端和 Python 预测服务由同一个进程提供。访客访问该服务的 HTTPS 地址，在网页上选择日期、模型、时效和网格。数据和模型保存在运行服务的电脑上。

## 作者在 Mac 上开启临时演示

1. 解压 GitHub Releases 的完整包，在解压目录运行 `python3 start.py --port 8765` 安装依赖并检查本机预测。按 Ctrl+C 停止后，用 `.venv/bin/python scripts/serve_web_demo.py --port 8786` 启动演示服务。
2. 安装 [Cloudflare 的 cloudflared](https://developers.cloudflare.com/tunnel/downloads/)，另开一个终端运行 `cloudflared tunnel --url http://127.0.0.1:8786`。
3. 将终端给出的 `https://…trycloudflare.com` 链接发给演示访客。访客可直接在浏览器运行预测。保持 Mac 联网且预测服务和隧道都在运行。演示结束后按 Ctrl+C 停止隧道。

浏览器访客可运行预测和回测。近期观测由维护者从本机更新。

临时地址会随隧道重新启动而变化。[Cloudflare Quick Tunnel 文档](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

## 后续迁往长期托管

选用可长期运行 Python 或 Docker 的主机，将完整包解压到部署目录。安装 64 位 Python 3.13 和 `requirements.txt` 的依赖，保留 `data/`、`models/` 和 `dashboard/dist/`。使用以下命令启动，PORT 按托管平台设置：

```sh
python scripts/serve_web_demo.py --host 0.0.0.0 --port "${PORT:-8080}"
```

平台的 HTTPS 入口需要将网页和 `/api/` 转发到同一服务。使用 `GET /api/health` 确认 `artifacts_ok` 为 true，并从公网测试近期观测状态和预测。维护者可通过本机启动入口更新近期观测。更新后重启公开演示服务以重新加载缓存，托管平台应将缓存放在可写的持久化存储上。建议起步按 8 GB RAM 和 6 GB 可用磁盘规划，再按实际并发调节。

公开服务的访客隐私说明需按最终托管平台更新。
